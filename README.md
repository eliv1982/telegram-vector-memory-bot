# Telegram Vector Memory Bot

Telegram-ассистент на `aiogram 3` и Haystack с персональной векторной памятью и RAG по загруженным документам с указанием источников. Это один бот: он помнит, что пользователь ему писал, отвечает по PDF/DOCX из личной библиотеки пользователя и, если документы ответа не дают, передаёт запрос общему Agent'у с инструментами.

Интерфейс бота и ответы по документам — на русском языке.

## Возможности

- персональная семантическая память: каждое текстовое сообщение сохраняется в Pinecone и используется как контекст в следующих ответах;
- точная дедупликация памяти (всегда включена) и опциональная, по умолчанию выключенная семантическая дедупликация;
- загрузка PDF и DOCX, конвертация и разбиение на фрагменты через Docling, индексация в Pinecone;
- краткое резюме загруженного документа одним предложением;
- ответы по документам со ссылками на источники (страница для PDF, номер фрагмента для DOCX);
- строгий контракт ответа по документам: если модель не вернула проверяемое подтверждение, ответ по документам не показывается;
- переход к Haystack Agent с памятью и инструментами (погода, курсы валют, время, праздники, информация о PyPI-пакетах), когда по документам ответить нельзя;
- изоляция данных по пользователям: отдельные Pinecone namespace для памяти и для документов;
- работа только в личных чатах, long polling;
- команды `/start`, `/help`, `/memory`, `/forget_me`.

## Как это работает

Обычное текстовое сообщение проходит такой путь:

1. Бот обслуживает только личные чаты. В группах, супергруппах и каналах обновление не доходит ни до одного обработчика.
2. **Recall.** Из namespace памяти пользователя извлекаются `MEMORY_TOP_K` ближайших записей. Порога релевантности нет: возвращаются ближайшие записи, даже если они слабо связаны с вопросом.
3. **Попытка ответа по документам.** Вопрос превращается в embedding, из namespace документов пользователя извлекаются `DOCUSCOPE_RETRIEVAL_TOP_K` ближайших фрагментов, и модель получает их с метками `DOC_1`, `DOC_2`, …
4. **Проверяемый контракт.** Модель должна ответить одним JSON-объектом `{"answerable": true|false, "answer": "...", "source_ids": ["DOC_1"]}`. Ответ принимается, только если `answerable` равно `true`, текст не пуст, указан хотя бы один источник и **все** `source_ids` соответствуют фрагментам, реально переданным в prompt. Невалидный JSON, обычный текст, лишние или недостающие поля, неизвестный идентификатор источника — всё это отклоняется (fail-closed). Единственное допущение — одна внешняя обёртка Markdown code fence. Решение о маршруте принимает только этот разбор, а не сравнение текста ответа с какой-либо фразой.
5. **Ответ по документам.** Если контракт выполнен, бот отправляет ответ и компактный блок источников (не более двух). Источниками становятся только фрагменты, на которые сослалась модель.
6. **Fallback.** Если документов нет, они не содержат ответа, ответ модели не прошёл проверку или поиск/генерация завершились ошибкой, запрос передаётся Haystack Agent. Воспоминания передаются ему как недоверенный контекст, а не как инструкции; доступны инструменты (Open-Meteo, курсы валют, локальное время, Nager.Date, PyPI).
7. **Remember.** После успешной отправки ответа исходный текст сообщения записывается в память. Если ответ не удалось сформировать или отправить, сообщение в память не записывается.

Попытка ответа по документам предпринимается для каждого обычного текстового сообщения. Если у пользователя нет загруженных документов, поиск ничего не возвращает и бот сразу переходит к Agent, не вызывая chat-модель для ответа по документам (вопрос при этом всё равно превращается в embedding и отправляется в Pinecone).

### Загрузка документа

1. Пользователь отправляет PDF или DOCX. Проверяются расширение, MIME-тип (если он указан) и размер (`DOCUSCOPE_MAX_FILE_BYTES`).
2. Файл скачивается во временный каталог и удаляется после обработки; исходный файл нигде не хранится.
3. Docling конвертирует документ и разбивает его на структурированные фрагменты. Пустые фрагменты отбрасываются; максимум — `DOCUSCOPE_MAX_CHUNKS_PER_DOCUMENT`.
4. Идентификаторы фрагментов детерминированы и строятся из хеша содержимого файла, поэтому повторная отправка того же файла перезаписывает фрагменты, а не дублирует их.
5. Haystack ingestion pipeline строит embeddings и записывает фрагменты в Pinecone. Бот проверяет, что записано ожидаемое число фрагментов.
6. Второй pipeline формирует резюме одним предложением на русском языке. Если не удалось только резюме, бот сообщает, что файл сохранён и по нему можно задавать вопросы.

### Haystack в проекте

Pipeline'ы индексации и резюме запускаются через `Pipeline.run()`. Для ответа по документам собирается Pipeline `text_embedder → retriever → prompt_builder → generator`, но сервис вызывает его компоненты по одному, чтобы проверить ответ модели между шагами; `Pipeline.run()` для этого пути не используется. Agent — это `haystack.components.agents.Agent`.

## Память

- Сохраняется исходный текст сообщения пользователя, а не извлечённые факты и не ответы бота.
- **Точная дедупликация всегда включена:** сообщение с тем же нормализованным текстом (регистр, пробелы, Unicode-нормализация) повторно не записывается.
- **Семантическая дедупликация по умолчанию выключена** (`MEMORY_SEMANTIC_DEDUP_ENABLED=false`). Если включить её, сообщение пропускается как дубликат, когда ближайшая запись имеет cosine similarity не ниже `MEMORY_SIMILARITY_THRESHOLD` (по умолчанию `0.50`); исключение — случай, когда явное отрицание («не», «нет», «not», «never» и т. п.) есть только в одном из двух текстов: тогда сообщение всё равно сохраняется. Порог применяется **только** при явно включённой семантической дедупликации, он не откалиброван и не является проверенным значением. Режим экспериментальный: высокая схожесть не отличает перефразировку от обновлённого факта («живу в Берлине» и «теперь живу в Париже»), поэтому новый факт может быть отброшен.
- Логики замены или обновления устаревших фактов нет: старые записи остаются и могут вернуться при recall.
- Recall возвращает `MEMORY_TOP_K` ближайших записей без порога релевантности.

## Команды

| Команда | Действие |
|---|---|
| `/start` | Приветствие и список команд. |
| `/help` | Справка по командам и загрузке PDF/DOCX. |
| `/memory` | Показывает, сколько записей памяти сохранено у пользователя. Загруженные документы не учитываются. |
| `/forget_me` | Удаляет **и** семантическую память пользователя, **и** его загруженные документы (оба namespace). Обе операции всегда выполняются независимо друг от друга; об успехе бот сообщает, только если удалось обе. Если одна не удалась, сообщает, что часть данных могла сохраниться, и предлагает повторить. |

Документ загружается обычной отправкой файла. Другие типы файлов получают сообщение о поддерживаемых форматах, а нетекстовые сообщения без файла (фото, стикеры и т. п.) — сообщение о том, что бот понимает только текст. Неизвестные команды получают ответ со ссылкой на `/help`.

## Данные и приватность

**Что хранится в Pinecone**

- *Память:* текст каждого сообщения как есть, числовой Telegram user ID, хеш содержимого, время создания и вектор embedding. Имя пользователя, ответы бота и история чата не сохраняются.
- *Документы:* текст каждого фрагмента, имя файла, хеш файла, номер фрагмента, номер страницы и заголовки (если доступны), тип содержимого, время загрузки, числовой Telegram user ID и вектор embedding.
- Данные каждого пользователя лежат в его собственных namespace: `{MEMORY_NAMESPACE_PREFIX}-{user_id}` для памяти (по умолчанию `telegram-user-{user_id}`) и `telegram-documents-user-{user_id}` для документов. Namespace строится только из числового user ID.

**Что отправляется внешним сервисам**

- *OpenAI или другой OpenAI-совместимый API* (`OPENAI_BASE_URL`): текст сообщений (embeddings для памяти и для поиска по документам), фрагменты документов (embeddings при загрузке), начало документа в пределах `DOCUSCOPE_MAX_SUMMARY_CHARS` символов (резюме), вопрос вместе с найденными фрагментами (ответ по документам), сообщение вместе с найденными воспоминаниями (Agent).
- *Pinecone:* все записи, перечисленные выше.
- *Telegram:* сообщения и файлы проходят через Telegram Bot API.
- *Публичные API инструментов Agent:* параметры, которые модель извлекла из запроса, — город (Open-Meteo), валюты (open.er-api.com), страна и год (Nager.Date), название пакета (PyPI). Инструмент времени работает локально.

**Ограничения и гарантии**

- Бот работает только в личных чатах; в группах он не отвечает и ничего не сохраняет.
- Автоматического срока хранения нет: данные остаются до вызова `/forget_me`.
- `/forget_me` удаляет оба namespace пользователя в Pinecone. Он не удаляет данные, уже переданные Telegram или провайдеру модели, и не очищает логи.
- Собственные журналы приложения не содержат текст сообщений и документов. В них попадают имена событий, типы ошибок и аргументы вызовов инструментов Agent (например, название города). Уровень `DEBUG` включает подробные логи сторонних библиотек, которые могут содержать тексты запросов; используйте его только локально.
- Проект не заявляет соответствия GDPR или иным требованиям и не проходил сертификацию для production-использования.

## Настройка окружения

Настройки читаются из переменных окружения и из файла `.env` в **текущем каталоге**, поэтому бот запускают из корня репозитория. Шаблон: `.env.example`. Секреты в репозиторий не попадают: `.env` и `.env.*` (кроме `.env.example`) исключены через `.gitignore`.

Обязательные:

| Переменная | Назначение |
|---|---|
| `TELEGRAM_BOT_TOKEN` | Токен бота от [@BotFather](https://t.me/BotFather). |
| `OPENAI_API_KEY` | Ключ OpenAI или совместимого провайдера. |
| `OPENAI_CHAT_MODEL` | Имя chat-модели (для ответов, резюме и Agent). Значения по умолчанию нет. |
| `PINECONE_API_KEY` | Ключ Pinecone. |
| `PINECONE_INDEX_NAME` | Имя уже существующего индекса Pinecone. |

Необязательные:

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `OPENAI_BASE_URL` | не задана (OpenAI) | URL OpenAI-совместимого API, `http(s)://…`. |
| `OPENAI_EMBEDDING_MODEL` | `text-embedding-3-small` | Модель embeddings. |
| `MEMORY_SEMANTIC_DEDUP_ENABLED` | `false` | Включает экспериментальную семантическую дедупликацию. Точная дедупликация работает всегда. |
| `MEMORY_SIMILARITY_THRESHOLD` | `0.50` | Порог cosine similarity, `0…1`. Действует только при `MEMORY_SEMANTIC_DEDUP_ENABLED=true`. |
| `MEMORY_TOP_K` | `5` | Сколько записей памяти возвращает recall, `1…20`. |
| `MEMORY_NAMESPACE_PREFIX` | `telegram-user` | Префикс namespace памяти (буквы, цифры, `-`, `_`). |
| `LOG_LEVEL` | `INFO` | `DEBUG`, `INFO`, `WARNING`, `ERROR` или `CRITICAL`. |
| `DOCUSCOPE_MAX_FILE_BYTES` | `20971520` | Максимальный размер загружаемого файла, байт. |
| `DOCUSCOPE_MAX_CHUNKS_PER_DOCUMENT` | `2000` | Максимум непустых фрагментов в одном документе. |
| `DOCUSCOPE_EMBEDDING_DIMENSIONS` | `1536` | Размерность embeddings документов; должна совпадать с размерностью индекса. |
| `DOCUSCOPE_RETRIEVAL_TOP_K` | `4` | Сколько фрагментов документов извлекается для ответа, `1…20`. |
| `DOCUSCOPE_MAX_SUMMARY_CHARS` | `12000` | Максимум символов документа, передаваемых для резюме. |
| `DOCUSCOPE_MAX_QUESTION_CHARS` | `4000` | Максимальная длина вопроса для поиска по документам; более длинное сообщение сразу уходит в Agent. |

Префикс `DOCUSCOPE_` — историческое имя настроек документного блока и не связан с названием проекта.

### Требования к индексу Pinecone

Бот **не создаёт** индекс; его нужно создать заранее (например, в консоли Pinecone). Код проверяет индекс и отказывается с ним работать, если:

- индекс не существует или не готов (для памяти это проверяется при запуске, для документов — при первом обращении к ним);
- метрика индекса не `cosine`;
- размерность embeddings не совпадает с размерностью индекса. Для памяти это размерность вектора, который возвращает `OPENAI_EMBEDDING_MODEL`; для документов индекс должен совпадать ещё и с `DOCUSCOPE_EMBEDDING_DIMENSIONS`. Несовпадение обнаруживается при первой записи или поиске.

С настройками по умолчанию (`text-embedding-3-small`) нужен индекс с размерностью `1536` и метрикой `cosine`. Память и документы используют один и тот же индекс, но разные namespace. Приложение удаляет только namespace конкретного пользователя и никогда не удаляет сам индекс.

## Установка

Нужен Python 3.11 или новее (CI использует 3.11). Зависимости описаны в `pyproject.toml`; `requirements.txt` содержит только `-e .`.

**Windows PowerShell**

```powershell
git clone https://github.com/eliv1982/telegram-vector-memory-bot.git
cd telegram-vector-memory-bot
py -3.11 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
python -m pip install -e ".[dev]"
Copy-Item .env.example .env
```

**Linux / macOS**

```bash
git clone https://github.com/eliv1982/telegram-vector-memory-bot.git
cd telegram-vector-memory-bot
python3.11 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
# Только Linux, если CUDA не нужна (как в CI): сначала CPU-сборка PyTorch.
python -m pip install torch torchvision --index-url https://download.pytorch.org/whl/cpu
python -m pip install -e ".[dev]"
cp .env.example .env
```

Затем заполните `.env` (см. таблицы выше).

Примечания:

- Docling тянет за собой PyTorch. Без шага с CPU-сборкой на Linux `pip` установит сборку с CUDA и несколько гигабайт пакетов `nvidia-*`. На Windows и macOS отдельный шаг не нужен.
- Для запуска без тестов и линтера достаточно `python -m pip install -e .`.
- На Windows установка PyTorch и Docling может упереться в ограничение длины пути (`MAX_PATH`). Если `pip` сообщает об ошибках длинных путей, создайте виртуальное окружение в коротком каталоге (например, `C:\v`) или включите поддержку длинных путей.
- При первой конвертации Docling может скачать модели и токенайзер с Hugging Face Hub (скачиваются только файлы моделей, содержимое документов никуда не отправляется), поэтому нужен доступ в сеть и свободное место на диске.

## Запуск

Из корня репозитория, при активированном окружении:

```bash
python -m hay_v2_bot
```

- бот работает через long polling и останавливается по `Ctrl+C`;
- нельзя одновременно запускать два процесса polling с одним токеном Telegram;
- `python -m hay_v2_bot.main` использует тот же runtime;
- более ранний вариант без документов (только память и Agent) запускается командой `python -m telegram_vector_memory_bot.bot`.

### Live smoke-скрипты

Скрипты в `scripts/` работают с реальными сервисами и **не входят** в набор тестов. Запускайте их вручную, только с синтетическими данными.

| Скрипт | Что делает |

| `smoke_test_document_rag.py` | Полный цикл документного RAG (Docling, Pinecone, OpenAI) для синтетического документа; удаляет записанные фрагменты и проверяет, что они исчезли. |

## Ограничения

- только личные чаты; группы и каналы не поддерживаются;
- поддерживаются только PDF и DOCX; для PDF номер страницы зависит от метаданных, для DOCX в источниках указывается номер фрагмента;
- память не заменяет устаревшие факты: старые и новые записи сосуществуют;
- семантическая дедупликация экспериментальная и по умолчанию выключена; её порог не откалиброван;
- recall не имеет порога релевантности;
- ответ по документам проверяется только структурно (формат и принадлежность источников переданным фрагментам); смысловую обоснованность ответа бот не гарантирует;
- бенчмарка качества поиска пока нет;
- нет интерфейса управления отдельными документами: удалить можно только все данные пользователя через `/forget_me`;
- нет срока хранения, ограничения частоты запросов и списка допущенных пользователей;
- long polling в одном процессе; заявлений о масштабируемости для production или SaaS проект не делает;
- внешние API могут быть временно недоступны.
